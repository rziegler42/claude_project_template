# Template repository plans

Plans for changing this template repository itself. They follow the lifecycle
and formats in `base/docs/plans/README.md`; `next.md` is the sole active plan.

## Archives

| Plan | Status | Outcome |
|---|---|---|
| [0001](0001-module-installer.md) | Completed | Modular `install.py` replaces `cp -R`; base and opt-in modules; explicit git identity |
| [0002](0002-runner-stub-hints-prompts.md) | Completed | Runner contract stub in the `claude` module, module post-install hints, prompts validated before asking |
| [0003](0003-installer-security-review.md) | Completed | Two adversarial security reviews of `install.py`; hardened reads and writes, scrubbed git environment, `--skip-unsafe-entries`; ADR 0002 |
| [0004](0004-plan-review-module.md) | Completed | Tool-neutral `plan-review` module: bounded read-only plan review policy and a Second opinion receipt in plans and archives |
| [0005](0005-codex-module.md) | Completed | Harness-marked `codex` module on top of `plan-review`: concrete Codex plan-review guidance and receipt mapping |
| [0006](0006-external-module-core.md) | Completed | `name=path` in `--with` and `--add`: standalone projects with a `template-module/` descriptor install as modules (fragments only), recorded in the manifest |
| [0007](0007-registry.md) | Completed | Machine-local registry: `--register`, `--unregister`, `--list` for standalone projects, and registered names in `--with` and `--add` |
| [0008](0008-external-module-review.md) | Completed | Adversarial review of the external-module and registry paths; seven findings fixed with regression tests, ADR 0002 addendum, ADR 0003 (Accepted) |
| [0009](0009-installer-update.md) | Completed | `--update`/`--upgrade` refreshes installed built-in and external modules in a project: blocks re-rendered, missing files written, differing files kept; security review skipped by the owner |
| [0010](0010-installer-module-removal.md) | Completed | `--remove` takes installed built-in and external modules out of a project: blocks stripped, unedited module files deleted descriptor-relative, manifest updated; adversarial review fixed four defects |
| [0011](0011-consistent-multi-item-options.md) | Completed | `--with` accepts space-separated modules like `--add`, `--update` and `--remove`, and still accepts commas; ordering hint when the target is swallowed |
| [0012](0012-owned-files-only-updates.md) | Completed | `--update` and `--add` patch blocks only in template-shipped files, and `--update` keeps existing blocks in `docs/plans/next.md`; completed project plans are no longer rewritten |
| [0013](0013-unique-active-plan-titles.md) | Completed | The empty `next.md` heading is the placeholder `# REPLACE_WITH_PLAN_TITLE` and the plans README requires a unique active-plan title, so review tools no longer see new plans as already reviewed |
| [0014](0014-report-and-merge-template-updates.md) | Completed | `--update` lists every file it leaves alone and whether the template changed it since install (base rebuilt from git history); opt-in `--update --merge` merges template changes three-way, leaving conflicts untouched; adversarial review fixed one medium and four low findings |
| [0015](0015-module-type-and-locations-in-the-manifest.md) | Completed | Built-in modules may declare `type`, `paths` and `data` in `module.json`; the installer records them as the manifest's `module_info` (`--new`, `--add`, `--remove`, full `--update`) for skills and modules to discover each other |
| [0016](0016-external-modules-in-the-manifest.md) | Completed | External modules may use `module_format` 2 to declare `type`, `paths` and `data`; every external module's `module_info` entry also records its `store` location (`../name` or absolute), refreshed by every verified `--update`; older installers refuse such manifests |
| [0017](0017-harness-file-specification.md) | Completed | Approved specification `docs/specs/module-harness-files.md` and an ADR 0002 addendum for harness files in modules; ADR 0004 accepted; reviewed by Codex (3 rounds, not converged) and two adversarial security passes; documents only |
| [0018](0018-harness-directories-and-harness-option.md) | Completed | Built-in modules may ship `harness/<harness>/`; `install.py --harness` installs those files into the harness root, records them in a `schema` 2 manifest (`harness`, `harness_files`), and `--add`, `--update` and `--remove` cover them; older installers refuse such manifests; two adversarial reviews fixed nine findings |
| [0019](0019-freecad-scripts-pilot.md) | Completed | `cad-freecad` ships the `freecad-scripts` skill in `harness/claude/` (12 files, four paths rewritten to be project-relative), installed with `--harness claude`; real-module tests, a hint and README updates; the first module to use harness files; no security review (no code changes) |
| [0020](0020-declarations-and-reporting.md) | Completed | Built-in modules may declare `helpers`, `workers` and `global_config` in `module.json`; `--new`, `--add` and `--update` report each as present or missing (helpers on `PATH`, worker roles from `harness.json`, the harness's global-config marker, `--global-config`) without installing, running or failing; one adversarial review, two Low findings applied |
| [0021](0021-verilog-sby-formal-skill.md) | Completed | `formal` ships the `verilog-sby-formal` skill in `harness/claude/` (two files, copied unchanged), installed with `--harness claude`; real-module tests for every `--add` path, a hint and README updates; no security review (no code changes) |
| [0022](0022-graphify-tooling-in-the-graphify-module.md) | Completed | The `graphify` module ships the Graphify workflow tool (`tools/graphify/workflow.py` with `status`, `doctor`, queries and explicit `refresh-code`, `prepare`, `finalize`; no hook and no post-commit step) and, with `--harness claude`, the `graphify-workflow` skill and `graphify-semantic` agent, with the first real `helpers`, `workers` and `global_config` declarations; two adversarial reviews fixed 4 Medium and 13 Low findings |
| [0023](0023-retire-the-harness-flag.md) | Completed | `claude` becomes base harness files (`base/harness/claude/`, supplier `base`) with a `.gitignore` harness block; the `claude` module and `"harness": true` are retired (`--with`/`--add claude` alias, `--update` migration); `codex` is a tool module with the `second-opinion` skill in `harness/claude/`; one adversarial review, three Low findings fixed |
| [0024](0024-external-stores-harness-files.md) | Completed | A registered `module_format` 3 store may ship `harness/claude/` skills, agents and commands: `--register` prints a review (files, SHA-256, units, findings, digest), `--approve DIGEST --name` pins an approval beside the registry, every install verb re-checks it, a changed store is refused or skipped until approved again; strict store tree rules, declarations for stores; one adversarial review, one Low and four Info findings fixed |
